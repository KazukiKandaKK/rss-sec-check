# DBの分け方:テーブル設計の判断基準

## 適用場面

新しいテーブルを設計するとき、または既存のテーブルの正規化・非正規化を見直すときに、このskillを読む。

## 対象範囲

このskillが扱うのはテーブル設計(正規化・非正規化)である。DBインスタンスやスキーマを業務領域ごとに物理的に分割するかどうかは、dddスキル の境界づけられたコンテキストの判断に委ねる。

## 正規化・非正規化の判断

正規化を優先するか非正規化を許容するかは固定ルールで決めず、以下を自問してその都度判断する。

- このデータへの読み取り頻度は、更新頻度と比べてどうか。読み取りが著しく多い場合、非正規化の余地がある。
- 重複させた場合、更新時に同期が必要な箇所はいくつあるか。多いほど不整合のリスクが高まる。
- 結合(JOIN)によるパフォーマンス低下は、実測または想定でどの程度か。

これらの問いへの答えを踏まえ、正規化を維持するか非正規化を許容するかを判断する。判断に迷う場合は、まず正規化された状態で実装し、実際にパフォーマンス上の問題が確認されてから非正規化を検討する。
