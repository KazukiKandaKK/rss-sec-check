# インフラ(AWS)の構成方針

## 適用場面

AWSのインフラ構成(ECSサービスの分割、RDSインスタンスの構成など)を設計・変更するときに、このskillを読む。

## コンテナオーケストレーション:ECS/Fargate

コンテナオーケストレーションにはECS/Fargateを用いる。EKSは用いない。

## サービス構成:今は1つのECSサービス

コード上は業務領域ごとにディレクトリが分かれている(backend-goスキル 参照)が、デプロイは今のところ1つのECSサービスとして行う。実行時は同一プロセスとして動作する。

これは dddスキル の戦略的DDDで確定した「境界づけられたコンテキストは事前に固定せず、通信は今は同一プロセス内の直接呼び出しでよい」という方針と一貫させるための構成である。将来、特定の業務領域を独立してスケールさせる、または独立したサービスとして切り出す必要が出た時点で、その業務領域だけを別のECSサービスに分離することを検討する。

## データベース:今は1つのRDSインスタンス

RDSも同様に、今は1つのインスタンス(1つのDB)を全業務領域で共有する。将来、特定の業務領域を切り出す必要が出た時点で、そのタイミングでDBの分離も合わせて検討する。
